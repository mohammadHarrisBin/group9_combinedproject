================================================================================
               CIRCULAR BUFFER SIMPLE MOVING AVERAGE (NAIVE SMA)
================================================================================

1. WHAT IS AN SMA?
--------------------------------------------------------------------------------
A Simple Moving Average (SMA) is the unweighted arithmetic mean of the last N 
prices. As new trades arrive, the oldest price falls out of the calculation 
window and the newest price takes its place.

- Short SMA (e.g., N = 3) : Responds quickly to recent price changes.
- Long SMA  (e.g., N = 5) : Smooths out noise to show the broader price trend.


2. THE CIRCULAR BUFFER MECHANISM
--------------------------------------------------------------------------------
Instead of shifting elements in an array (which is slow), we use a fixed-size 
array and a moving index called "head" that wraps around using modulo math:

    head = (head + 1) % capacity

Example: Window Size N = 3 (Array indices 0, 1, 2)
--------------------------------------------------------------------------------
- Trade 1 (Price = 100): Store at array[0]. head becomes (0+1)%3 = 1. [Count = 1]
- Trade 2 (Price = 102): Store at array[1]. head becomes (1+1)%3 = 2. [Count = 2]
- Trade 3 (Price = 104): Store at array[2]. head becomes (2+1)%3 = 0. [Count = 3 -> FULL]
  Current Window = [100, 102, 104]. Average = 306 / 3 = 102.00

- Trade 4 (Price = 106): Store at array[0] (Overwrites 100!). head = (0+1)%3 = 1.
  Current Window = [106, 102, 104]. Average = 312 / 3 = 104.00


3. NAIVE COMPUTATION VS. OPTIMIZED COMPUTATION
--------------------------------------------------------------------------------
- Stage A (Naive SMA) : Re-sums all N elements in the array on every trade.
                        Time Complexity per trade = O(N).
                        
- Stage B (Running SMA): Subtracts oldest price and adds newest price using a 
                        running sum formula (S_t = S_{t-1} + p_t - p_{t-N}).
                        Time Complexity per trade = O(1).


4. WHY WE BUILD THE NAIVE VERSION FIRST
--------------------------------------------------------------------------------
1. Correctness Benchmark: The naive re-sum approach is simple and virtually 
   impossible to mess up, serving as ground truth for testing.
2. Performance Baseline: In Stage B, we will compare the execution time of 
   Naive O(N) vs. Running-Sum O(1) to measure performance speedup for our report.
